# 지시서(TASK) 쓰는 법 (사람 2026-11-13)

TASK = 사람의 지시. **무엇이 되면 끝인지**와 **사람이 볼 곳**만 쓴다. 어떻게(고칠 파일·순서·작은 조각·시험 고르기)는 세션이 정한다(CLAUDE.md '묻지 않고 넘어간다').
TASK 를 처음 쓰는 쪽(사람·대화 Claude·세션)이 모두 이 틀을 따른다. 세 저장소(Historiamicrobattle · historia-headless · Historia)가 같은 틀.

## 틀

```markdown
# TASK_<갈래>_<이름> — 한 줄 요약 (날짜)

## 0. 사람 (사람 말 그대로 · 날짜 시각)
- "…"

## 1. 목표
다 되면 게임에서 무엇이 달라지나 — 2~3 줄.

## 2. 단계
순서: X1 → X2 → X3   ← 순서는 이 줄 하나에서만 바꾼다

### X1 이름
- 결과: 플레이어가 보는 변화 한두 줄
- 끝 기준: 숫자·시험 이름·대본 표 (예: 대본 k1 누른 점 ↔ 1열 끝 0.5 m 안 · 시험 Move.DragChain 통과)
- 사람 확인: 없음 | 무엇을 보고 무엇을 정하나 (세션이 보여 줄 것 — 표·스크린샷 몇 장)
- 참고(있으면): 코드에서 본 의심·함수·줄 — 세션이 재서 확인

## 3. 미리 정한 답
- 갈릴 만한 곳과 그 답 (예: 약탈 중 적이 오면 = 모임 · ○○ 값은 '미시 전투' 표 안에서 조정해도 됨)

## 4. 하지 말 것 (있으면)
```

## 규칙
1. **단계 경계 = 사람이 결과를 봐야 하는 곳.** 볼 필요 없으면 한 단계로 묶는다. 그 안의 작은 조각은 세션이 시작할 때 오류 구역마다 미리 나눈다(조각 하나 = 1~3 번 안에 고쳐질 크기).
2. **끝 기준은 숫자·시험으로** — 세션이 혼자 통과를 판단해 다음 단계로 넘어갈 수 있게. 숫자로 못 쓰는 것(보기 좋은지 · 느낌)만 '사람 확인'.
3. **TASK 안에 '판단 필요(사람이 정함)'를 미리 두지 않는다.** 쓸 때 보이는 갈림은 '미리 정한 답'에 답을 적는다. 답을 아직 모르면 '사람 확인'에 — 무엇을 보여 주면 정할 수 있는지와 같이.
4. **사람 답으로 TASK 를 늘릴 때**(R9·R10 …): 같은 틀의 단계를 '2. 단계' 아래에 덧붙이고, 순서는 맨 위 '순서' 줄만 고친다(절마다 '— ○○ 보다 먼저'를 흩어 쓰지 않음). 사람 말은 '0. 사람'에 날짜와 같이 덧붙인다.
5. **작업 방식을 TASK 에 다시 쓰지 않는다** — 빌드·시험·커밋·보고 양식·창 없이 등은 CLAUDE.md 에 있음. TASK 에는 그 TASK 만의 것만.
6. 옛 TASK(이 틀 전)는 그대로 읽되, 끝 기준이 없는 단계는 세션이 숫자 기준을 정해 STATUS 에 한 줄 적고 진행한다.
